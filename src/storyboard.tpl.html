Zero Latency: Anatomy of Local-First Sync

Eight key frames from the explainer, drawn by the same scene code as the player at the times shown, with each beat's on-screen text, transition and sound cues.

Facts and numbers assumed

  • 280 ms is an illustrative cloud round trip (phone to server and back). Real mobile round trips vary widely, roughly 50 to 300+ ms. The counter runs in slow motion so the wait reads.
  • 0 ms means no network wait. A write to the device's own database (IndexedDB, SQLite) still takes a fraction of a millisecond to a few milliseconds.
  • The outbox stands for the queue of pending changes (an operation log) that a sync engine sends whenever a connection is available.
  • The merge example uses two edits to different fields (title on Phone A, due date on Phone B), which a CRDT keeps both of. For two edits to the same field, a CRDT picks a deterministic winner (for example last-writer-wins), so every copy still converges.
  • CRDTs are named as the merge method because they are the common local-first choice; some systems use operational transforms or server-side reconciliation instead.
  • Phones stand in for any client device, and the server stands in for any sync peer or relay.
